# prune — markdown-only reference

With no ductus runtime registered, the host reaches the same result with its own file tools — no shell-pipeline substitution — producing byte-for-byte the output the primitives would write (the two-paths guarantee, §runtime-host-integration) — with one bound, stated under **reset** and **the design record** below: the reset body and the design-record heading set are compiled into the primitives from the framework templates, so a project that has customized its own tasks or plan template diverges there, and only there.

**Where a named section lives.** This file is read alongside its command, `prune.md`, which is already loaded whenever this one is. A section named below that has no heading in this file is in the command file, along with the numbered Instructions steps this file cites. A bare `§name` is a heading in this file or a marker in the constitution, `.ductus/constitution.md`; a `§name` with another file's path on the same line is a heading in that file, unless it is a constitution marker.

**`tasks.md`.** Segment it with the same grammar every tasks command uses (see [data-model](https://github.com/stonean/ductus/blob/main/specs/041-task-pruning/data-model.md)): detect flat (`## N.`) versus phased (`### N.` under `## …` containers), then split the file into its preamble, phase containers, and task sections. Classify each task section by its checkboxes — **spent** (≥ 1 checkbox, all checked), **pending** (any unchecked), or **no-checkbox** (zero checkboxes) — counting only real task-list checkboxes (a `- **Done when**:` line is not one).

- **keep-pending** (default): preserve the preamble and every pending / no-checkbox section verbatim; drop every spent section; in a phased file drop a phase container all of whose task sections were dropped, and keep one that governs no task section. When nothing is spent, leave the file byte-for-byte unchanged. Normalize seams to a single blank line with one trailing newline.
- **reset** (`--reset`): preserve the file's existing `# …` heading and replace everything below it with the template's initial tasks body (the intro line plus the guidance comment). On the runtime path this body is **compiled into** `prune-tasks`, pinned to `framework/templates/spec/tasks.md`, so an adopter who customizes `specs/templates/tasks.md` gets the framework body on the runtime path and their own template only on this markdown-only path. Refuse unless the spec status is `done` or `--force` is supplied; a file with no `# …` heading is malformed and is left untouched.

**`plan.md`.** A section is a `##` heading and every line up to the next heading at level 2 or above; a `###` stays inside its section, and a heading inside a fenced block or an HTML comment is not a heading. The lines before the first `##` are the preamble and are always kept.

- **The design record** is the `##` headings of the project's plan template, `specs/templates/plan.md`, compared case-insensitively and with nothing else forgiven, so *Tradeoffs* does not match *Trade-offs*. On the runtime path the set is compiled into `prune-plan` from the framework's own template, `framework/templates/spec/plan.md`, so an adopter who customizes theirs sees their own set only on this markdown-only path. A design-record section is never removed.
- **Decided** — a section is kept without being proposed when `analysis.md`'s `decisions:` list stores a `discarded` decision under `plan-record — plan.md §{heading} is outside the design record`, or one the host matches to it by judgment.
- **Removal** — delete the confirmed section, then normalize every seam in the file to a single blank line with one trailing newline, as keep-pending does. Re-read the section immediately before removing it; if it changed since it was judged, judge it again.
- **Reopen** — on a `done` spec, compare against HEAD (`git diff HEAD -- "specs/{feature}/"`): the spec reopens when `tasks.md` adds an unchecked checkbox — holds an unchecked checkbox line, trimmed and outside fenced blocks and HTML comments, more times than HEAD's does, so a line moved or re-indented adds nothing. Compare once before the first write, for the preview, and once more after the run's writes to the spec, which decides the reopen (step 9). A `tasks.md` absent at HEAD triggers nothing. Anything else leaves the spec `done`, a `plan.md` edit included, whatever it corrects (§spec-lifecycle).

**`--all`.** Walk every feature directory under the spec root in corpus order — sequential directories by number, then branch-scoped ones grouped by identifier and ordered by their counter numerically, so `1234.2-` precedes `1234.10-` — and apply the reductions above to each. Count every directory walked; list each spec with something to reduce, and each `done` spec whose tree requires a reopen, with its status; and name each spec with no `tasks.md` or no `plan.md`. Refuse `--force` alongside `--all`.

**`--project`.** Read `AGENTS.md` at the project root and `system.md`, `events.md` and `errors.md` under the spec root, reporting a missing file as absent and one that cannot be read as not examined. Split each into entries by the grammar in [data-model](https://github.com/stonean/ductus/blob/main/specs/041-task-pruning/data-model.md) §`prune-project`: nothing inside a fenced block, an HTML comment or a `ductus:` managed region is an entry, and a `#` or `##` heading is structure. For an `events.md` or `errors.md` entry, take its identifier by the same grammar and search the project's files outside the spec root and the four subjects for it as a literal string with the host's search tool; a search that also reads files the repository ignores can only add hits. Judge and confirm each entry as the command's **Project files (`--project`)** says. Re-read an entry immediately before removing or replacing it; if it changed since it was judged, judge it again. After a removal or replacement, collapse the blank lines at the changed seam to at most one, and rewrite nothing else in the file. A missing `system.md`, `events.md` or `errors.md` home is created with its `#` heading only, since an adopter's tree holds no copy of the project templates; on the runtime path `prune-project` creates it from the framework template instead.

Confirm with the user before every write, write atomically (a temp file then rename), and leave no backup — recovery is git history.
