# 086 — Review records hold only what their scope judged

A spec's `review.md` records the outcomes of its own review's scope, and a later run drops what that scope will not judge again.

## Motivation

- An adopter's `review.md` reached about 518 KB. Its frontmatter, copied without its body, was 140,562 bytes, of which `decisions:` was 129,546 (92%): 206 entries decided on 2026-11-23 and 2026-11-24, 150 of them a person's deferrals to about 20 other specs' `spec.md` or `tasks.md` and 56 waivers, 55 by the rule; 203 were anchored to a file, 154 files in all. Method: each copied line's UTF-8 length plus its newline, summed by top-level frontmatter key; entries counted as list items under `decisions:`. The body was not copied, so its findings and its 741 excluded paths were not examined.
- The owner's account (2026-11-24): `/{project}:review --all` ran with that spec as the session target and recorded every spec's outcomes in its record. `framework/commands/review.md` runs `--all` once per feature, each into its own record, but nothing enforced it: `write-review` refused an `unread` entry the scope did not hold and accepted a finding or observation on any file (`departure_waiver_entries`' doc: such a finding "stays counted"). The copy alone could not confirm the account, since code naming no spec sat in every open spec's scope under spec 081 and could have put those files there too.
- No re-run cleared them. `process-decisions` expired a decision whose file was deleted (`RunScope::why_unread`) and retained one whose file existed but which the run's scope did not hold, since absence proved nothing ([079](../079-review-and-analysis-work-converges/spec.md)). A decision on a file that never belonged to the spec was therefore kept forever.
- [084](../084-reopen-for-owed-code-review-every-code-change/spec.md)'s AC6 moves code no spec claims out of every open spec's scope into `{specs-root}/review.md`, which would make each decision already stored on such code in a feature's record permanent there, while the project record starts without them and asks again.

## Behavior

- `review.md`, like `tasks.md`, is not a durable artifact (owner, 2026-11-24; §implement-phase: nothing durable goes in a review record's body). A deferral's durable home is the task, scenario or criterion it wrote, so a stored decision only spares a later run from asking again, and dropping one costs at most that question.
- A review records only outcomes on files its own scope holds, so a collapsed `--all` run cannot write one spec's outcomes into another's record.
- A file belongs to a spec when the spec's plan names it, by the match `compute-review-scope` applies to a plan entry, or a commit attributed to the spec changed it. A decision or waiver anchored to a file that does not belong is not carried past the spec's next unrestricted review. One on a file that belongs but is unchanged since its last review is carried, since since spec 081 a review's scope is only what changed, and dropping it would ask again on every incremental review. A history the walk cannot read whole, as in a shallow clone, is reported as not examined and drops nothing.
- A deleted file's decision expires as it does today.
- A review with no recorded run reads every file that belongs to the spec, its plan's entries and the files its attributed commits changed, so the list it starts from is derived rather than kept by hand. Affected Files stays the design's expected files.
- `/{project}:prune` reduces `review.md` between reviews, since under 084 a `done` spec is reviewed only when its code changes: it drops each decision and waiver anchored to a file that does not belong, and rewrites each Excluded from scope entry still carrying the claiming specs written before `ductus-v0.60.0` as its bare path, leaving every other field and section as the run wrote it.

## Edge Cases

- An observation that names no file is not refused, since it has no file the scope could hold.
- A finding the passes report on a file the run's scope does not hold is not the run's to record. A gating one is fixed in the run when the fix is mechanical, or deferred to the home **§Groom decision tree** in `.ductus/reference/groom.md` chooses, each put to the operator. Any other is named in the run's report and recorded nowhere.
- The criteria step's verdicts are keyed to a criterion, not a file, so a criterion whose code lies outside the scope is judged and recorded as before.
- A restricted review, by a dimension flag or `--since`, drops no decision by the ownership rule, since it did not evaluate every source.
- `/{project}:prune` refuses, writing nothing and naming the file, a `review.md` whose record or `decisions:` list does not parse, so an undeterminable record is never rewritten as though it were read; it leaves a record carrying `fix-rounds-open: true` as it is, for the run that holds it.
- A prune and a review writing one record at once: the write guarded against a lost update (`BE-TXN-002`) refuses the later, which runs again from a fresh read.
- A key several specs' records hold is judged in each record against that record's spec alone.

## Cost

> **Signpost:** [089 — The pipeline's own cost is stated and bounded](../089-the-pipeline-s-own-cost-is-stated-and-bounded/spec.md) has each spec that adds a check, a field or a primitive state what a run of it costs and what it retires.

Measured at `0a04268d` on Darwin arm64 (Apple M4 Max), with no other build running, over this repository's 83 feature directories and the 5,228 commits reachable from `HEAD`. A time is wall seconds, the range of five runs after a warm-up. A size is the characters of a result's or a tool's text as `scripts/measure-result-sizes.sh` records them over its generated corpora (small, 10 specs; large, 100), unless it is stated in bytes, of a CLI result over this repository.

- **The ownership walk.** Timed by `std::time::Instant` around the call in an ignored release test, never committed, in a detached worktree at `0a04268d`; a commit is diffed when `Attributor::may_claim` names an asked spec. 022 alone took 2.362 to 2.394 s, 912 commits diffed, 656 paths; 087, a spec of fewer than 50 commits, 0.263 to 0.267 s, 33 diffed; 089, 0.139 to 0.141 s, 16 diffed; one walk over all 83 specs, 7.371 to 7.407 s, 4,701 diffed.
- **What it adds to a first review.** On 086 itself in that worktree, its boxes and criteria ticked and its record on disk with none at `HEAD`: `compute-review-scope` took 0.674 to 0.748 s, `write-review` with no outcome 0.678 to 0.683 s, and `check-review-gate`, which reached its `review-owed` read, 0.840 to 0.889 s. Each made one walk, by a test-only counter, and 086's own walk takes 0.244 to 0.248 s, 20 commits diffed. A later review's scope makes none; a classifier walks only when an unfired entry on a file outside the scope reaches the ownership test.
- **`prune-review`.** The release CLI in a `git clone --local` copy at `0a04268d`, timed by `time.perf_counter` around the process. A preview of 022's record (150,914 bytes, 13 drops) took 2.485 to 2.679 s for a 3,375-byte result; of 087's, with nothing to drop, 0.334 to 0.344 s, 407 bytes; of a spec with no record, 0.009 s, with no walk. With `all` it took 8.197 to 8.338 s for a 192-byte result in the file form, its lists file 174,216 bytes over the 61 records it listed. Applying 022's took 2.705 to 2.713 s, and the applying walk over the 61, each run on restored records, 8.291 to 8.716 s.
- **Result sizes.** `prune-review` returns 237 characters for one feature and, with `all`, 805 on the small corpus and 7,199 on the large, inline at the default read size. Over a record holding 300 waivers and 300 decisions on files no spec owns, it returns 57,838 for one feature and 58,597 to 64,991 with `all`, 473 and 193 at the default read size once its lists move to the file. `process-waivers` and `process-decisions` over that record return 88,479 and 95,788, and 273 and 292 at the default read size; with nothing to drop, 174 and 203, against 143 and 172 at `1718c8c1`, the 31 characters of an empty `dropped` and its count. `compute-review-scope` returns 2,216 on the small corpus and 37,892 on the large, against 1,798 and 36,449 at `1718c8c1`; only 086's commits changed its code since.
- **Loaded schema**, a tool's description plus its input schema as compact JSON. `prune-review`'s is 3,291 plus 1,166. Since `1718c8c1`, the descriptions tasks 2 to 4 change grew: `write-review`'s by 293 characters, `process-decisions`' by 652 and `process-waivers`' by 647, each of those two input schemas by 72 more, and `compute-review-scope`'s by 652, 2,388 in all.
- **What it retires.** No check, field or primitive. Every function, type, constant and public field 086's commits removed from `runtime/src` was rewritten in place (the four descriptions, `read_anchors`, `Retained::ALL`, a renamed test), and nothing but `write-review`, which renders it, and `prune-review` reads a `## Excluded from scope` line. The drop ends only the indefinite retention of an unfired entry, a behavior rather than a check, and `prune-review` takes no existing primitive's work: `prune-tasks` and `prune-plan` each own another file.

## Acceptance Criteria

- [ ] AC1: `write-review` refuses, writing nothing, a finding or an observation on a file the run's scope does not hold, naming the file, and a test proves the refusal and fails with it removed.
- [ ] AC2: After an unrestricted `/{project}:review`, the spec's `review.md` carries no stored decision or waiver that did not fire, anchored to a file the run's scope does not hold, its plan does not name and no commit attributed to it changed, and still carries such an entry whose file its plan names or such a commit changed, unchanged since its last review; the run names each entry it drops for not belonging apart from those whose finding stopped firing; a fixture proves both directions, and one whose history is cut reports the spec not examined and drops nothing.
- [ ] AC3: A decision on code no spec claims, stored in a feature's `review.md` before 084's scope change, is dropped from it by that spec's next unrestricted review or by `/{project}:prune` once the change lands, and is not written into `{specs-root}/review.md`; a fixture proves it.
- [ ] AC4: A decision anchored to a deleted file still expires on an unrestricted run, and a test proves it.
- [ ] AC5: `/{project}:prune` drops from a spec's `review.md` each decision and waiver anchored to a file that does not belong to the spec, naming each, and rewrites each Excluded from scope entry that carries claiming specs as its bare path, leaving every other field and section byte-identical; a fixture proves both, and that a record with nothing to drop or rewrite is left byte-identical.
- [ ] AC6: `compute-review-scope` for a spec whose `review.md` at `HEAD` records no run puts in the scope each existing file a commit attributed to the spec changed, as well as each plan entry; a fixture proves a file changed by such a commit and absent from the plan joins the scope, and one whose history is cut reports the history not examined rather than a complete scope.

## Applicable Rules

- `QUAL-CLAIM-001` — a decision dropped because its file does not belong to the spec is reported as dropped, never as a finding that stopped firing.
- `QUAL-TEST-001` — each fixture fails with its behavior removed.
- `QUAL-DELEG-001` — the ownership rule replaces the retention test `RunScope::why_unread` applies, so each decision that test kept is accounted for.
- `BE-TXN-002` — `/{project}:prune`'s write to `review.md` refuses when the record changed since it was read.

## Resolved Questions

- **One new spec for both halves**, the out-of-scope outcomes and the retained decisions, rather than an open question on 084, the inbox, or a scenario under [066](../066-audit-records-and-the-completion-gate/spec.md) or 079: the agent's recommendation, adopted by the operator, 2026-11-24. **Why split from 066-audit-records-and-the-completion-gate:** 066 owns the audit records, the completion gate and the primitives that write and classify the records, while this spec states one requirement those primitives carry out, that a record holds only what its scope judged; it changes 066's surfaces itself, as `AGENTS.md`'s shared-surface rule directs (owner, 2026-11-04), and 066 links back.
- **A file belongs to a spec when its plan names it or a commit attributed to it changed it** (the agent's recommendation, adopted by the operator, 2026-11-24). Of the 1,791 file-anchored decisions in this repository's review records, 544 were on files both named and changed, 840 changed only, 28 named only and 379 neither, so the rule drops 379. Method: a commit counted as a spec's when its subject's scope named the spec's number or it touched the spec's directory, an approximation of the runtime's attribution; plan entries matched as exact path, glob or directory; counted at `8fe7e6f3`. Rejected: the plan alone, dropping 1,219, 840 of them on files the spec's own commits changed; history alone, dropping 407, 28 of them planned and not yet changed; the run's `excluded` set, which never drops a decision on a file untouched in the window, so a collapsed `--all` run's entries stay.
- **A review keeps carrying `decisions:` and `waivers:`, pruned by the rule above** (the agent's recommendation, adopted by the operator, 2026-11-24). The record is not durable, but its stored decisions spare a person the same question and keep a re-run's dispositions what the last run decided (079). This repository's 77 review records carried 1,791 decisions, about 838 KB: 693 waivers the rule decided and 1,098 a person did, 943 waivers and 155 deferrals, 93 of them under the outcome names from before spec 076; 1,629 were decided before their record's last run; `waivers:` held 3 entries, 1,549 bytes. Same method and commit as above, bytes counted per entry's lines. §implement-phase's "keeping only its waiver and decision lists" stands. Rejected: carrying only a person's decisions, which drops the 693 rule waivers for the rule to decide again when each fires, at a cost to convergence that was not measured; and carrying neither, which asks each of the 1,098 person decisions again when its finding fires and stops a deferral releasing its violation until it is deferred again.
- **`/{project}:prune` reduces `review.md`: it drops what does not belong and rewrites old Excluded from scope entries as bare paths** (the owner's question, 2026-11-24; the agent's recommendation, adopted by the operator, 2026-11-24). This repository's 77 records held 8,573,661 bytes, 26 of them over 50,000; Excluded from scope sections were 6,843,625 bytes, 814,458 as bare paths, 32 records still carrying the claiming specs `64946fe7` stopped writing, which nothing read; the rule above drops 379 entries, about 177 KB at the mean entry's 468 bytes. Same method and commit. Prune's artifact table, spec 041's, classed `review.md` as regenerated and never written, so 041 is cross-spec impact. A write to `review.md` leaves the spec's analysis stale, which no gate reads on a `done` spec (`framework/reference/analyze.md` §Analyze state drift (blocking)). Rejected: dropping entries only, which keeps 6.03 MB of claimant lists until each spec's next review; and leaving prune as it was, under which a `done` spec keeps both until its code changes.
- **AC2 judges a stored entry that did not fire, on a file the run's scope does not hold** (the agent's recommendation, adopted by the operator, 2026-11-24). An entry that fired was read by the run, whether its file is in the scope as the spec's own change, uncommitted work, a carried open finding or a folded-in path, and an outcome the run records is on a file the scope holds (AC1). Rejected: dropping those too, which drops the run's own decisions on the spec's uncommitted code and asks them again at the next review.
- **A gating finding on a file outside the scope goes to its home** (the agent's recommendation, adopted by the operator, 2026-11-24). The passes read related files, so a review can still find an issue in another spec's code, which AC1 no longer lets it count. Of this repository's 1,791 file-anchored stored decisions, 379 were on files outside their spec's plan and commits (the count above); how many were gating was not counted. Each such finding adds at most one task to the spec that owns its file, which reopens a `done` one by 084's state rule. Rejected: recording it nowhere, which leaves a gating issue with no disposition (§design-principles).
- **The refusal needs no exception for the criteria step**, which yields verdicts, never findings or observations (`framework/commands/review.md` step 7.2: one met or not-met verdict per criterion; `framework/reference/review.md` §Criteria step; `write-review`'s `criteria` argument, `{label | index, met, note}`). An observation naming no file is outside the refusal. The agent's reading, confirmed by the operator, 2026-11-24. Rejected: refusing an observation that names no file too, which would make a pass name a file for a cross-file observation.
- **Decisions on code no spec claims are dropped by the rule above, not moved to `{specs-root}/review.md`** (the agent's recommendation, adopted by the operator, 2026-11-24). This repository's records held 86 such decisions under 79 keys, a file counted as claimed by no spec when no plan named it and no attributed commit changed it: 72 waivers the rule decided, and 5 deferrals and 9 waivers a person did; 5 keys sat in more than one record, none with conflicting outcomes. Same method and commit. The project record asks a person again for at most those 14, each only when its file changes under no spec after 084's seed while its finding still fires. Rejected: moving them, which needs a second guarded record write from a feature review or prune and a merge rule for keys several records hold.
- **A review with no recorded run derives its files: the plan's entries and the files the spec's attributed commits changed** (the owner's question, 2026-11-24; the agent's recommendation, adopted by the operator, 2026-11-24, which replaced its earlier recommendation of an enforced Affected Files once the backlog below was measured). Of 10,035 pairs of a spec and an existing code file its attributed commits changed, 8,146, across 78 specs, were in no plan: an upper bound, since the method above gives a commit's every file to each spec whose directory it touches where the runtime splits such a commit by plan. Same commit. Affected Files stays the design's expected files, which attribution still reads, and §plan-phase is unchanged. Rejected: (A) a durable `files.md` at a fixed path, the owner's proposal, which would add an artifact type, backfill 78 spec directories and every adopter's by a migration, touch about eight commands and primitives, and take about 150 of the constitution's 481 bytes of headroom, with the same backlog to fill; (B) Affected Files enforced by a check that it lists every attributed file, which would report that backlog on its first run.
