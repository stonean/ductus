# A-path-argument-resolves-inside-its-base

## Context

`BE-INPUT-004`, rewritten 2026-10-19, says filesystem operations "MUST resolve the canonical path and verify it falls within the expected base directory before opening the file", and its Verification asks for "path canonicalization followed by a containment check that compares whole path components". The runtime's check is `validate_no_traversal` (`runtime/src/primitives/mod.rs`). It works on the text alone: it refuses an empty, absolute, rooted, drive-prefixed or `..` path, and it does not follow a symlink. A symlink inside the project that points outside it, either tracked in a cloned repository or created locally, therefore passes the check, and the primitive then reads, writes, deletes or runs whatever is on the other side.

Probed 2026-10-20 through the release binary, with a scratch project whose links point to a directory outside it:

- `set-status` on a feature directory that is a symlink to an outside directory rewrote that outside directory's `spec.md`.
- `create-scenario` on a feature whose `scenarios/` is a symlink to an outside directory wrote the new scenario there and reported it as `specs/001-x/scenarios/s.md`.
- `mark-task` on a `tasks.md` that is a symlink to an outside file read the outside file's content. It wrote nothing outside: `write_atomic_bytes` renames a tempfile over the link, so the link was replaced by a regular file inside the project carrying the edited content.
- `merge-managed-block` on a `CLAUDE.md` that is a symlink to `AGENTS.md` in the same project replaced the link the same way, so the block landed in a new, separate `CLAUDE.md` and `AGENTS.md` was left without it. `/ductus` calls `merge-managed-block` on both files (`framework/bootstrap/ductus.md` §Shared constitution imports).
- `std::fs::canonicalize` returns `NotFound` for a path that does not exist yet, and on macOS it maps `/tmp/…` to `/private/tmp/…`.

The 42 production call sites of `validate_no_traversal`, counted 2026-10-20, fall into three groups:

- 32 take a feature argument, a feature name joined to the spec root or a feature path joined to the project root, in `interpreter/mod.rs` and 29 primitives. 16 of those primitives write or delete, by a token count of their write, rename, create and remove calls.
- 7 take a file or directory path that is opened, in 6 primitives: `apply-manifest`'s source and destination, `enforce-manifest`'s cleanup directory, `merge-managed-block`, `merge-permissions`, `migrate-session-file`, and `run-generator`, which passes its script to `bash`. Every one of these primitives writes, deletes or executes. The paths `/ductus` passes them are the **Shared Files** manifest destinations (`.ductus/constitution.md`, `specs/rules/*.md`, `specs/templates/*.md`, `.githooks/*`, each agent's command directory), the per-agent `ductus` install path, `.gitignore`, the active config file, and the native rules files `CLAUDE.md` and `AGENTS.md`.
- 3 record a path in a session file and never open it: `write-session`'s `path` and `scenario-path`, and `retarget-sessions`' loop over the same two. `BE-INPUT-004`'s trigger, a file opened based on input, does not fire on these.

The `writeCode` write boundary (`validate_write_code_boundary`, `runtime/src/schema/extensions.rs`) matches each edit path against glob patterns after a lexical screen. The runtime never opens those paths: the host applies the edits. So the boundary is a containment decision the host relies on, not a check before the runtime opens a file.

067 already settled a symlink question for the files `check-artifacts` opens through a sibling link, and settled it without canonicalization (`specs/067-analyze-and-audit-checks/scenarios/sibling-symlink-trust-boundary.md`). Its `traverses_symlink` (`runtime/src/primitives/check_artifacts.rs`) uses `symlink_metadata` to ask whether any component below the base is a link, never where it points. A linked target is skipped as `target-unparseable` and the run continues. The reason it gives is the repeat-run determinism 045's AC8 requires: canonicalization "fails on a legitimately-missing target and makes the answer depend on where a link points". Two more 067 scenarios resolve lexically for the same reason (`link-adjacent-drift-family`, `adopter-corpus-link-integrity`). This repository tracks no symlinks.

## Behavior

- One shared check in `runtime/src/primitives/mod.rs` decides containment, after the existing lexical screen. It refuses a path that can reach outside its base through a symlink. How it decides is the first open question below.
- The base is the directory each primitive names: the project root for a feature argument and for a project path, and `apply-manifest`'s `source-root` and `target-root` for its source and destination. A staging directory outside the project is a legitimate `source-root`.
- A refused path is an `InvalidPath` error naming the argument and the link that took it outside. The error comes before the primitive reads, writes, deletes or runs anything.
- After the check passes, the primitive keeps using the path it was given and keeps naming it that way in results and errors.
- The `writeCode` boundary applies the same check to each edit path before matching it against the boundary's globs, so a boundary of `runtime/**` does not admit `runtime/link/x` when `runtime/link` points into `framework/`.
- The three session-file sites keep the lexical check alone, because they open nothing.
- Which call sites go through the check is the second open question below.

## Edge Cases

- A project in a repository subdirectory (059) is contained by its project root, not by the work tree's root, so a link to a sibling directory in the same repository is refused.
- A symlink created between the check and the open is not caught. The check runs once at the start of each call.
- A primitive that walks the corpus without a path argument (`derive-dependencies`, a sibling spec read from frontmatter by `traverse-deps` or `diff-cross-spec`) opens nothing based on input, and this scenario does not change it.
- `extract-archive` skips symlink entries, so a staging `source-root` holds none.

## Open Questions

- **How does the check decide that a path leaves its base?** Measured 2026-10-20. (a) **Canonicalize and compare.** Canonicalize the joined path and accept it only when it lies inside the canonicalized base, compared by whole components (`Path::starts_with`). For a path that does not exist yet (a new scenario, an `apply-manifest` destination), canonicalize its deepest existing ancestor and append the rest. A dangling link is judged by where its target would resolve. Both sides are canonicalized, so macOS's `/private/tmp` and Windows' `\\?\` forms compare equal. A link that stays inside the base is accepted, so `merge-managed-block` keeps replacing an in-project `CLAUDE.md -> AGENTS.md` link with a separate file, as probed today. The answer depends on where a link points, the property 067 avoided for its check results. It matches `BE-INPUT-004`'s wording, so the plan statement needs no further argument. (b) **Refuse any link.** Move 067's `traverses_symlink` into `mod.rs` and refuse a path when any component below its base is a symlink, wherever it points. No destination is read, so the answer depends only on whether a link is present, which is 067's determinism property. There are no missing-path, dangling-link or platform canonical-form cases. With `..`, absolute and rooted paths already refused and no link below the base, the path as given is its own canonical form under the base. The plan statement has to make that argument, because `BE-INPUT-004` names canonicalization. It also refuses links that stay inside the project: `/ductus` would halt at §Shared constitution imports for a project whose `CLAUDE.md` links to `AGENTS.md`, where today it silently splits the two files. How many adopting projects carry an in-project link on one of the paths above cannot be counted from this repository. Only an adopter report or a survey of adopting projects would settle it. Recommended: (a). It refuses everything (b) refuses that leaves the project and nothing that stays inside, so it adds no new refusal for an adopter layout. The population that would decide against it is the one that cannot be measured here. Its costs are the missing-path and platform cases, and an answer that depends on link destinations, which matters for a containment refusal less than for 067's reported results.
- **Which call sites go through the check?** Measured 2026-10-20, and the same under either answer to the question above. (a) **Every site that opens a path, plus a walk of each checked feature directory.** 39 sites (32 feature-argument and 7 file-path) go through the check. A feature-argument call also lists the feature directory recursively (78 files at most in this corpus, 022's) and is refused when any link in it fails the check. That stops all three probed escapes, the read through a symlinked file included, without touching the files the primitives open beneath the directory. It overrides 067's skip-and-continue for the links that fail the check: `check-artifacts` would refuse the whole call where `sibling-symlink-trust-boundary` promises a `target-unparseable` skip. So (a) either exempts `check-artifacts` from the walk, or edits that scenario on 067, which is `done`, at the cost of a reopen and a full five-pass re-review of 067. Exempting it leaves `check-artifacts` reading a fixed-name file through a link that leaves the project, as (b) leaves every primitive. (b) **Every site that opens a path, with no walk.** The same 39 sites, and `create-scenario`'s destination is checked whole, because its slug names it. It stops the symlinked feature directory and the symlinked `scenarios/`. It still lets a primitive read through a fixed-name file or subdirectory beneath a checked feature directory (`spec.md`, `tasks.md`, the `scenarios/` listing), as `mark-task` read the outside `tasks.md`. Writes to a fixed-name file stay inside, because `write_atomic_bytes` replaces the link. Checking each of those opens instead would mean at least 92 filesystem calls in the 29 feature primitives (32 of them writes or deletes). That count is a lower bound, from a token count of non-comment lines before each file's tests, and it misses the helpers in `mod.rs`. (c) **The feature-argument sites alone.** 32 sites, with no walk. This is the form 063's routed finding names, its `feature` argument, but not all of what 022's names, which is every host- and LLM-supplied path. The 7 file-path sites stay lexical, and all six of their primitives write, delete or execute: `apply-manifest`, `merge-permissions` and `merge-managed-block` can write through a symlinked parent directory such as `.claude/`, `enforce-manifest` and `migrate-session-file` can delete through one, and `run-generator` can run a script that lies outside the project. 13 other specs' plans name one of those six primitives. Every option changes 063's plan and 022's plan, and none changes the three session-file sites. Recommended: (a), with `check-artifacts` exempt from the walk so 067 stays closed. It is the one option that stops every probed escape, and it costs the same 39 sites as (b) plus one directory listing per feature call.
