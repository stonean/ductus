- [ ] Constitution §recommendations, through 050's back-edge: an owner's answer is applied as the chosen option reads, and a refinement the sources suggest (narrower, broader, or reshaped) goes back to the owner as its own question before it lands. On 2026-10-20 one owner question (BE-AUTHN-018 against saved recovery codes) existed only because the text applied for 008's BE-AUTHN-022 answer departed from the chosen option, and a review caught a second departure (NIST's code-plus-authenticator route narrowed to the password).
- [ ] check-review-gate never reads `should-violations`, so a spec with an outstanding SHOULD passes the pre-`done` gate and is then flagged at `done` by check-artifacts' blocking `review-state-drift`. Cause, read at HEAD f24c55c6: `check_review_gate.rs` halts on `review.blocking` alone, which only MUST violations set, while `check_artifacts.rs` treats `should_violations > 0` on a done spec as blocking. Repro (0.59.11): an in-progress spec whose review.md records `should-violations: 1` and `blocking: false` before its current analysis was recorded; `check-review-gate --feature <it>` answers `{"passed":true}`. Suggested fix: halt on `should-violations > 0`, pointing at review.md's Waived findings, with a fixture test.
- [ ] A criterion's checkbox is inside the analysis digest, so ticking criteria after /analyze stales it at the pre-`done` gate. Measured 2026-10-25 on 0.59.11 and HEAD f24c55c6: an in-progress spec whose gate passed answered `blocked-by: analyze-stale` naming its `spec.md` once `mark-criterion --label ACn` unticked one criterion, and passed again once it was ticked back. Adopters learn to tick before analyzing, or to analyze twice. Design question: leave checkbox state out of the analysis digest (the gate reads the ticks itself), or state the order in /implement's completion steps.
- [ ] check-artifacts' path-existence families (criterion paths, body paths) run only on a `done` spec, and an in-progress run reports them as neither a finding nor a skip, so the analysis that satisfies the pre-`done` gate never exercises them and its `unexamined: 0` reads as complete. Measured 2026-10-25 on 0.59.11 and HEAD f24c55c6: a done spec with 4 body-path findings gave 0 findings and an empty `skipped` once its status was set to in-progress. Suggested fix: report a status-gated family as skipped (a reason such as `status-gated`), or run it at in-progress too, with a fixture test.
- [ ] validate-frontmatter checks a scenario against the spec schema: pointed at a scenario whose frontmatter is only `section:`, it answers hard-fail `status is missing` and `dependencies is missing` (0.59.11 and HEAD f24c55c6, 2026-10-25). Suggested fix: pick the scenario schema for a path under `scenarios/`, or refuse a non-spec path, with a fixture test.
- [ ] compute-review-scope derives two wrong scopes (0.59.11 and HEAD f24c55c6, 2026-10-25). (a) An Affected Files cell naming two backticked paths (`` `a.md` / `b.md` ``) puts only the first in `plan-affected`, so the second is reviewed only if it changed since the base. (b) A file deleted since the diff base is listed in `scope` and `modified-since` though it cannot be read, so `examined` falls short of `scope`. Suggested fix: take every backticked path in a cell, and leave deleted paths out of the scope or list them apart, each with a fixture test.
- [ ] The CLI forms of write-review, process-waivers and process-decisions take no findings, fired anchors or observations: write-review's flags are --feature, --reviewed-at, --reviewed-against, --diff-base, --scenario, --empty-scope, --summary, --skipped-pass and --examined (0.59.11 and HEAD f24c55c6, 2026-10-25). Recording a review outside an MCP host therefore means driving `ductus mcp` over stdio from a script. Suggested fix: an `--input FILE` (or stdin) form taking the same JSON as the MCP tool.
- [ ] read-tasks reads only the first line of a task's `Done when`. Repro (0.59.11 and HEAD f24c55c6, 2026-10-25): append `## 99. Probe`, `- [ ] one` and `- **Done when**: first line` followed by an indented continuation `second line` to a tasks.md; `read-tasks --feature <it>` returns `"done-when": "first line"`. Cause: the parser takes the bullet's first line. Suggested fix: join the bullet's indented continuation lines, with a fixture test.
- [ ] append-task numbers a task one past the highest left in tasks.md, so after /prune drops the highest task the next append reuses its number, and a commit or record citing the pruned task's number then names two tasks. Measured 2026-10-25 on 0.59.11 and HEAD f24c55c6: with tasks 2 and 3, removing 3 and appending gave `## 3.` again. Design question; suggested fix: number past the highest ever used, e.g. a `next-task` counter like `next-criterion`.
- [ ] apply-manifest accepts an incomplete substitution map in silence: it rejects a braced or empty key (`validate_substitution_key`), but nothing in the runtime checks the written text for a placeholder left unsubstituted, so a map missing a key writes `{key}` literally while `substitutions-applied` and `entries-substituted` read as a clean run (read in HEAD f24c55c6's source, not run). Suggested fix: report, or refuse, any of the source's known placeholders still present after substitution, honoring keep-literals, with a fixture test.
- [ ] Rule candidates no shipped rule covers (HEAD f24c55c6's framework/rules, read 2026-10-25). (a) security-backend: an HTTP client that sends a credential in a header of its own (an API-token header, not `Authorization`) MUST refuse redirects, since Go's net/http resends custom headers on a 307 or 308 to any host, stripping only `Authorization` and cookies when the host changes. (b) concurrency-backend: a transaction that locks child rows and then deletes or rewrites the set MUST lock the parent row first, since two that each lock one child and then delete all of them deadlock, and PostgreSQL aborts one after `deadlock_timeout`. (c) quality-cross: a test of a bound pins the figure its spec states rather than reading the constant it checks, so moving the constant fails it; perhaps an example clause in QUAL-TEST-001 ("one that pins only a value incidental to the behavior") rather than a rule of its own.
- [ ] Practices an adopter recorded locally that hold for every project running ductus, for the constitution or /review's source: record a decision as the operator's only when the operator made it ("the agent's recommendation, adopted by the operator, DATE" otherwise); name a function, test or file, never a line number, in tasks and decisions; a document follows a move by content, not file name, since a file a move split maps to as many paths as its parts went to; learn what a primitive does in a throwaway clone (`git clone --local` to /tmp, run with the main tree's binary); measure a reviewer's claim against the tree before recording it, breaking things in a clone while reviewers read; recommend a waiver only where a recorded requirement backs it, never for a cost; and before routing a review observation, ask whether it is design rationale, whose home is a short why at the code.
