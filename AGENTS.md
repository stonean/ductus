# `ductus`

The `ductus` framework — a pipeline-driven spec-to-implementation flow scaffolded into adopted projects.

> **Agents:** this file holds rules true of **this project alone**. Route a learning by who it is true for ([§drift-prevention](framework/constitution.md#drift-prevention)): a rule true for every project goes in the constitution. Append to the matching section; add one only if none fits.

## Constitution

See [constitution.md](framework/constitution.md) — guiding principles, development pipeline, spec lifecycle, and quality standards that govern this project.

## Project Structure

The `framework/` directory is ductus's source — everything that ships to adopted projects via `/ductus`. It is laid out by IA primary purpose, not by file kind:

- `framework/constitution.md` — the constitution shipped to adopted projects (lands at `.ductus/constitution.md` in adopter repos)
- `framework/rules/` — domain rule sets adopted projects can reference (security-backend, security-frontend, …)
- `framework/templates/spec/` — templates consumed by an agent during the pipeline (spec, plan, tasks, data-model, research, scenario)
- `framework/templates/project/` — project document templates consumed once at adoption (agents, claude-md, system, errors, events, project-readme, gitignore, inbox)
- `framework/commands/` — operational slash command sources only
- `framework/reference/` — each command's markdown-only reference, read when one of its steps points at it (lands at `.ductus/reference/` in adopter repos)
- `framework/bootstrap/` — the `ductus.md` installer plus per-agent permission files at `bootstrap/configure/{key}.md`

When adding files under `framework/`, place them by purpose, not by extension.

## Tech Stack

`ductus` is a text-first framework. The implementation is intentionally narrow:

- **Markdown** — every primary artifact (constitution, specs, plans, tasks, scenarios, rules, commands, templates) is plain markdown ([§text-first-artifacts](framework/constitution.md#text-first-artifacts)).
- **Bash scripts** under `scripts/` — generators (`gen-*.sh`), the pre-commit hook installer (`install-hooks.sh`), and lints (`lint-*.sh`). All deterministic; no application logic.
- **GitHub Actions YAML** under `.github/workflows/` — CI configuration only.
- **Node.js / `markdownlint-cli2`** — lint only; never a build dependency or published. `npm ci` installs it to `node_modules/`, which `lint-markdown` prefers. Child processes need the real Node `bin` on `PATH`, not an nvm function.
- **Rust** under `runtime/` — the `ductus` runtime crate (bin + lib, edition 2024, MSRV `1.89`, `rmcp` SDK). Capabilities are MCP tools unless `cli-only` in `framework/runtime-tools.txt`; it calls no LLM.

The runtime is required, acquired by the pipeline, and ships in lockstep with the framework, per [§runtime-boundary](framework/constitution.md#runtime-boundary), which rules out a database or long-running service. A `runtime/` change reaches adopters only via a `ductus-v<version>` tag.

For a further tooling-language decision (a second binary the framework might ship), prefer Rust, as the runtime does; Go is the credible alternative when development velocity matters more than production characteristics.

## Workflow

- **Commit directly to `main` — this repo uses trunk-based development.** Releases are cut from `main` by tag and `--ref=main` adopters track it: no release branch, no PR step. The branch-first default does not apply; branch only when the user asks (owner, 2026-06-11).
- **Review an external pull request for correctness and simplicity before resolving its conflicts or merging it — a clean merge and a green hook say nothing about whether the change is right.** Read the diff, run the full local gate on the PR tree from this repo, and check `done` specs' criteria before touching conflicts, then report; the user decides. Update a PR branch only when asked.
- **Never create a repository named `govern` under this account again, and never reuse a retired project name.** GitHub's rename redirect from [049](specs/049-rename-govern-to-ductus/spec.md) serves older adopters only while the name is unused; so the retired crates.io crate stays deprecated, never yanked.
- **A change ships via a `ductus-v<version>` tag — the commit alone reaches no default-source adopter.** Bump `version`, `runtime/Cargo.toml` and `runtime/CHANGELOG.md` in one commit, pushed with the tag in one sitting once affected specs are `done`; untagged pins halt `--ref=main` (owner, 2026-08-28).
- **A pushed tag is not a published release, and `release not found` is the *normal* answer for the ~11 minutes in between.** The `release-assets` job publishes it late. Check `gh run view <id> --json status,conclusion`: `in_progress` means wait; only `failure` is an outage. Never delete-and-re-tag an in-progress run.
- **`done` is not the same as *discharged* — the pre-`done` gate and the release audit are both blind to an obligation recorded in prose.** One held only in spec-body prose or `specs/inbox.md` passes `check-review-gate` and `scripts/audit/run-all.sh`. Before proposing `done` or tagging, re-read both for obligations.
- **A spec does not reach `done` with an outstanding SHOULD — every review finding is resolved or waived first, not only the MUST ones.** [§implement-phase](framework/constitution.md#implement-phase).
- **Work a recommendation out to its result *before* presenting it.** [§recommendations](framework/constitution.md#recommendations).
- **Never record anything durable in `review.md` — it is regenerated wholesale.** [§implement-phase](framework/constitution.md#implement-phase).
- **Run `scripts/audit/run-all.sh` after committing and before tagging — a green audit run before the commit is not evidence for any family that reads history.** [§grounding](framework/constitution.md#grounding).
- **When a scenario is recorded after the fix it describes has landed, review it with `--since`. The default window starts after the reopen and holds none of the code.** [§implement-phase](framework/constitution.md#implement-phase).
- **A review is the five passes, not the `write-review` call — never record findings you did not derive by reading the resolved scope.** Steps 3–7 of `framework/commands/review.md` are the command; `write-review`'s `examined` is self-reported. Load rules, read the scope, derive each count, and name in the Summary what went unread.
- **`examined` counts the in-scope files the passes *read*. A file you are confident about by other means is named in the Summary, never folded into the numerator.** [§implement-phase](framework/constitution.md#implement-phase).
- **When one commit reopens several specs, review their shared window once in depth and let each later review read only what changed since.** It also reads its artifacts and deliverable; its Summary says so. Carry the newest record's in-scope, still-holding `decisions:` with byte-identical text and disposition. Reviewers use `git show`.
- **Have an independent agent re-read each fix round before the review record is written, and state the severity bar in its brief.** A contrived input is a NOTE; re-reads re-run earlier probes. Stop at one with no MUST or SHOULD, fixing only correctness defects or sentences the round made untrue; name unread prose-only rounds.
- **Never record another project's name in this repository — describe the shape instead.** Specs, scenarios, changelogs, commits and doc comments may say what kind of project exercised something, never which (owner, 2026-08-17). Build any fixture under `/tmp` or `runtime/tests/fixtures/`.
- Read `framework/commands/{name}.md` before recommending, describing, or disambiguating a slash command — don't guess from the name. Source files are authoritative; the generated `.claude/commands/ductus/*.md` copies are produced by the pre-commit hook.
- **A `.ductus/config.toml` change is cross-spec impact only when it modifies a key another spec already documented.** [§cross-spec-impact](framework/constitution.md#cross-spec-impact).
- **A retired feature's spec is deleted, not left at `done`.** [§spec-lifecycle](framework/constitution.md#spec-lifecycle).
- **No dead references in live artifacts.** [§drift-prevention](framework/constitution.md#drift-prevention).

## Gotchas

- **Pi has no MCP client — its tool surface is the `.pi/extensions/ductus.ts` bridge, and never "fix" Pi by registering an MCP server for it.** `framework/bootstrap/pi/ductus-bridge.ts` stays stdio-only and dependency-free. After changing it, run `node scripts/tests/pi-bridge-harness.mjs`, then a real `pi` run, the only test of pi's loader.
- **After changing runtime source, verify through the built binary — not the MCP tools.** `mcp__ductus__*` runs the session-start binary: after `cargo build --release`, use `./runtime/target/release/ductus <primitive> …` or `cargo test`; restart the session to use a changed primitive.
- **`framework/commands/help.md` is generated — hand-edits to it are reverted on the next commit.** Edit `*_entries` arrays in `scripts/gen-help-tables.sh`, re-run it. Likewise `framework/bootstrap/configure/*.md` allow blocks, from `framework/runtime-tools.txt` via `scripts/gen-configure-mcp.sh`.
- **Registering a runtime primitive is five sites, and two of them are only found by tests — de-registering one is the same five.** `PRIMITIVE_REGISTRY`, a `#[tool]` or `CLI_ONLY_PRIMITIVES` entry, a `dispatch_primitive` arm, a `main.rs` `Command` (`runtime/src/`), and a `framework/runtime-tools.txt` tool or `# cli-only:` line.
- **`check-artifacts`' `skipped` array names targets that could not be *reached*, never subjects that were empty.** Its reason set is closed; a family with nothing to examine reports no finding and no skip. State bounded coverage once, in its doc comment and `framework/reference/analyze.md`, not as per-spec skips.
- Use `npx markdownlint-cli2` to run markdown linting — do not suggest installing it globally.
- **An `assessSpecQuality` step's prose chooses the tier of rules the exec walker asks about, so a `-tier` word added to that prose can change what the step covers.** `severity_from_step_prose` (`payload.rs`) takes the first `must-tier`/`should-tier`/`info-tier`. In `framework/commands/analyze.md` steps 11-12 write `a MUST or SHOULD keyword`; grep for `-tier`.
- **Two extension points fan out in the exec walker, so neither is a stand-in for "one request, one response" in a test.** `assessSpecQuality` asks per loaded tier rule; `askClarifyQuestion` per `open-questions` entry, or once if keyless (use that). Rule fixtures need a heading like `TS-MUST-001` and an RFC 2119 keyword.
- The command generator substitutes `{project}` → `ductus` and `{cli-config-dir}` → `.claude`, and writes `framework/bootstrap/configure/claude.md` as `configure.md` in the `ductus` command directory; the values are `PROJECT` and `CONFIG_DIR` in `scripts/gen-claude-commands.sh`.
- **An edit to `framework/commands/*.md` is invisible to that slash command until the generator re-runs — including to the command you are editing, in the same session.** The host loads the installed copy under `.claude/commands/ductus/`, which the pre-commit hook regenerates only at commit time. Run `scripts/gen-claude-commands.sh` before invoking an edited command.
- **The pre-commit hook lints and tests the working tree, not the commit, so unstaged runtime work rides along.** With `runtime/` staged, `.githooks/pre-commit` runs `cargo fmt --check`, clippy and `cargo test` on every file on disk. Finish or stash other runtime edits first, or gate on their lint.
- **Never `git add -A` / `git add .` in this repo.** [§text-first-artifacts](framework/constitution.md#text-first-artifacts).
- **The two frontmatter derivations are runtime primitives, not shipped scripts.** [§runtime-boundary](framework/constitution.md#runtime-boundary).
- `write_atomic_bytes` (the create-then-rename helper backing every primitive write) lands the destination at the tempfile's mode (`0600` on Unix) when new; a rewrite keeps its mode. A primitive creating a non-`0600` file re-applies it with `mirror_source_mode`, as `apply-manifest` does.
- `runtime/rust-toolchain.toml` pins `components = ["clippy", "rustfmt"]`, and every `cargo` command under `runtime/` auto-installs missing ones, hitting rustup's `detected conflict: 'bin/cargo-fmt'` bug; so such a workflow's `dtolnay/rust-toolchain` step sets `components: clippy, rustfmt`.
- **A new slash command wires into five places outside `framework/commands/`, and two of them are load-bearing for adopters.** The hook, Families 16 and 21 and `scripts/gen-help-tables.sh` cover four. Unflagged fifth: the list in `runtime/src/parser/mod.rs`'s `rewritten_command_files_parse_with_document_step_numbers`.
- `<!-- audit:ignore-promotion -->` silences the framework self-audit's Family-9 (primitive-promotion) check for a prose-only `## Instructions` step, but `ductus exec` still dispatches a backticked primitive there; to cite one undispatched, drop the backticks or move it out of the steps.
- **A markdown link in a spec body creates a `dependencies:` edge — cite in prose when you mean a citation.** [§text-first-artifacts](framework/constitution.md#text-first-artifacts).
- **`create-scenario` appends its own Open/Resolved Questions scaffolding — do not author those headings in the body you pass it.** [§scenarios](framework/constitution.md#scenarios).
- **Never write a literal `ductus-vX.Y.Z` into a `framework/commands/*.md` prose line — `BLESS` will template it into a time bomb.** `BLESS=1` in `runtime/tests/parity.rs` rewrites the current version to `{{runtime-version}}`; the golden breaks next release. Keep versioned accounts in `runtime/CHANGELOG.md`; read every bless diff.
- **Gitignored adopter state survives a `git` reset, so a "reset" subject is not a fresh one.** Reverting restores tracked files only; an untracked `.mcp.json`, `.ductus/bin/` and `~/.ductus/bin/ductus` keep the last run's state. Check bootstrap-test preconditions on the tree; save gitignored files first.
- **This repo's dogfooded copy of an adopter file is not the copy adopters get — test the shipped one.** `.githooks/pre-commit` (ours) and `framework/bootstrap/hooks/ductus-pre-commit` (shipped) are separate files. For anything the manifest ships, exercise the adopter's copy on an adopter-shaped tree.
- **A spec's review diff base moves forward on every reopen, so the window shrinks — measure it before reaching for `--since`.** [§implement-phase](framework/constitution.md#implement-phase).
- **Replacing a hand-rolled predicate with a shared one widens everything it was quietly doing, not just the part you meant to fix.** `QUAL-DELEG-001` in `framework/rules/quality-cross.md`.
- **`remove-inbox-item` takes the bullet text, so never drive it from line numbers — each removal shifts the lines under you.** [§brownfield-inbox](framework/constitution.md#brownfield-inbox).
- **A scenario's link to a sibling spec needs `../../`.** [§text-first-artifacts](framework/constitution.md#text-first-artifacts).
- **`path` is a reserved array in zsh and clobbering it destroys `PATH`.** The harness shell is zsh: never name a variable `path` or `status` (read-only `$?`; assigning it aborts, killing a background poll). Also avoid `argv`, `pipestatus`, `options`, `signals`, `ARGC`.
- **`gh run list --json headSha` returns the full 40-character sha, so a poll filtering on a short one never matches.** Pass the full sha (`--arg s "$(git rev-parse HEAD)"`) or compare `.headSha[0:8]`, and check the filtered set is non-empty: an empty selection and an unfinished run look the same.
- **An unquoted parameter does not word-split in zsh, so a built-up flag string arrives as one argument — and the primitive it was meant for answers confidently without it.** Build repeated flags as an array: `args=(); for f in framework/rules/*.md; do args+=(--rule-file "$f"); done; cmd "${args[@]}"`. `check-rule-ids`' `examined: 0` means nothing was checked.
- **A word starting with `=` is a command lookup in zsh, so an unquoted `======` separator kills the command it sits in.** zsh's `EQUALS` option expands `=word` to a command's path, so `echo ======` fails with `===== not found` and a `&&` chain stops there. Separate output with `---`, or quote the separator.
- **A colon after a parameter is a zsh modifier, so `git show $sha:AGENTS.md` reads the wrong path.** zsh applies modifiers (`:A`, `:a`, `:h`, `:t`…) to a bare `$name:x`, so `$c:AGENTS.md` becomes an absolute path and git reports `unknown revision`. Brace or quote it: `git show "${sha}:AGENTS.md"`.
- **`compute-review-scope` and `diff-cross-spec` blow the MCP output cap on a wide diff base, and the saved-output pointer is not a read.** [§grounding](framework/constitution.md#grounding).
- **In a `set -e` script, `[ test ] && cmd` as the *last* command of a block exits the script when the test is false.** Write `if [ test ]; then cmd; fi`, or `[ test ] || continue` in a loop; never `|| true`, which swallows a real failure. Check the last command of every block, loop, function and trap.
- **A feature directory is not necessarily `NNN-slug` — ask `parse_feature_dir`, never the first three bytes.** See [§numbering](framework/constitution.md#numbering-convention). Match `parse_feature_dir`'s `FeatureForm`; `1234.1-slug` is one too. Numbers: `sequential_number()`; order: `feature_dir_cmp`.
- **clap expands `{n}` in a doc comment as a newline, so a `#[derive(clap::Args)]` field's docs cannot contain one.** Those doc comments in `runtime/src/schema/primitives.rs` render as `--help`; write the placeholder as `<identifier>.<n>-<slug>`. Check with `cargo run -- <subcommand> --help`.
- **Verify that a recorded *decision* still holds, not only that a criterion does — a rejected alternative that was later adopted is invisible to every check.** Per [§drift-prevention](framework/constitution.md#drift-prevention), §Trade-offs, §Non-goals, Resolved Questions are live; `git log -S` the defining artifact. Pre-017 specs: check 017's reversals.
- **"Record" spans several destinations in this framework — name the artifact and section, never the verb alone.** [§pipeline-boundaries](framework/constitution.md#pipeline-boundaries).
- **Mutating code to prove a test fails: run unit tests in the dev profile, and rebuild the release binary after any parity mutation.** `scripts/mutation/run.py` runs unit tests only; add a mutation with its killing test, and `--check` after editing anchored code. A parity mutation is a separate `cargo test --release` run that leaves `runtime/target/release/ductus`, which `.ductus/bin/ductus` and the MCP server run, a mutant: `cargo build --release` after.
- **A retired filename is not a retired name — sweep it by meaning, not by token.** [§drift-prevention](framework/constitution.md#drift-prevention).
- **Piping a gate command's output replaces its exit status — `cmd | tail` reports `tail`'s success, not `cmd`'s.** [§grounding](framework/constitution.md#grounding).
- **A `§` reference resolves by *line*, and intra-document by longest-first heading match — a line wrap alone breaks it.** [§drift-prevention](framework/constitution.md#drift-prevention).
- **A `path:line` citation in a spec body is provenance, not a live claim — do not sweep them, and do not trust one either.** A rotted line number is not a defect. When one is stale, fix the surrounding sentence only if it asserts current behaviour, leaving the citation alone. Cite new ones as a file plus a symbol name.
- **A review record written before the record gained its coverage and digest fields is unexamined, not clean.** [§implement-phase](framework/constitution.md#implement-phase).
- **An acceptance criterion's parenthetical enumeration is a claim of its own, and it drifts from what the artifact does.** [§grounding](framework/constitution.md#grounding).
- **A spec with no recorded `in-progress` transition derives an *empty* diff base, and `write-review` then resolves `scope: 0`.** [§implement-phase](framework/constitution.md#implement-phase).
- **A cross-spec signpost is not rename residue — removing one silently falsifies another spec's ticked criterion.** [§drift-prevention](framework/constitution.md#drift-prevention) exempts it. To delete a `> **Note:**` or `> **Signpost:**`, first grep `specs/*/spec.md` for criteria asserting it. Use blockquotes.
- **A sweep must not rewrite the record of the thing being swept.** Rename maps, decision records, migrations, rejected alternatives and incident accounts keep the old name. After a sweep, grep its diff for `X → X` and read for inversions and multi-line collapses.
- **A sweep can make a quoted instruction point at itself, and the identical sentence may be correct one file over — classify by *who emits it*, never by the string.** [§drift-prevention](framework/constitution.md#drift-prevention).
- **A spec body must not carry a point-in-time status section — it goes stale silently and then contradicts its own frontmatter.** [§spec-requirements](framework/constitution.md#spec-requirements).
- **Only a spec's durable contracts stale its review — `scenarios/*.md` and `data-model.md`, nothing else — and that is what prices a corpus sweep.** [§implement-phase](framework/constitution.md#implement-phase).
- **`criterion-path-existence` only sees a path inside backticks — an unbackticked one is not a finding, not a skip, and not a candidate.** [§spec-requirements](framework/constitution.md#spec-requirements).
- **`unexamined` cannot be measured while the spec is `in-progress`, and the gate's own ordering is what hides that.** [§implement-phase](framework/constitution.md#implement-phase).
- **A spec's own completion commit can destroy content, and a `## Heading` absorbed into an unterminated code span is invisible to every check this project has — including the gate that reads it.** [§text-first-artifacts](framework/constitution.md#text-first-artifacts).
- **`process-decisions` with an empty `fired` expires every stored decision — fire each live finding's key first.** Omitting a live discard's key reports it `expired` and the next write drops it. Read the record's `decisions:` list, fire each key that still holds, and treat `expired` as a prompt to check.
- **`append-task` has two shapes that both return exit 0 while writing nothing, and neither is an error.** [§scenarios](framework/constitution.md#scenarios).
- **On the CLI, `append-task`'s `--body` takes one item per flag.** Use `--body=…` if an item starts with `-`; omit the `Implement the behavior…` line `--slug` adds. `--parent-heading` is the phase heading minus leading `##` and space, em-dash exact.
- **A primitive whose result has two shapes returns one struct with two flattened `Option` halves, and the halves must never share a key.** rmcp requires an object output schema, ruling out an untagged enum (`prune-tasks`, `prune-plan`); serde's flatten consumes a shared key even when that half fails. Keep a round-trip test per shape.
- **`set-status` takes `--from` and `--to`, not `--status` — and the refusal is the useful half.** [§spec-lifecycle](framework/constitution.md#spec-lifecycle).
- **A boolean argument is a valueless flag on the CLI and a JSON boolean over MCP — `--checked true` is an error, `--checked` is the call.** Over MCP pass `checked: true`. The CLI cannot pass `false`, so unticking with `mark-task` or `mark-criterion` is MCP-only. If a batch of calls fails uniformly, re-run one with its output shown.
- **A recorded measurement can encode a constraint you have not found yet — when a fresh derivation disagrees with a recorded one, hunt the constraint before concluding the record is wrong.** [§grounding](framework/constitution.md#grounding).
- **Git's `-E` is POSIX ERE and does not honour `\b`, so a word-boundary pattern silently under-reports.** Spell the boundary literally (the surrounding backtick, slash or space) or use `grep -P`; BSD `grep -E` is the same. When two greps disagree, re-derive both.
- **`cargo` exits 101 from the repo root, and 101 is also what a failing test suite returns — so a mis-rooted probe reads exactly like the failure it was meant to prove.** `Cargo.toml` is in `runtime/`: prefix each cargo call with its own `cd /…/ductus/runtime &&`, and confirm a failure from its output (`grep -E 'FAILED|assertion|panicked'`), not its exit code.
- **`/{project}:consolidate` migrates no content — it re-points inbound links and deletes the directory, scenarios and all. Migrate anything worth keeping by hand *before* `retire-feature`, or git history becomes the only copy.** Hand-correct referrers whose subject is the retiring spec, run `rewrite-spec-links` as a no-op proof, write the record into the target, then `retire-feature --allow-sequential`.
- **`grep` here is ugrep, and a bounded-context pattern exceeds its complexity limit — erroring once per file, which reads exactly like a scan that found nothing.** The `.{0,N}` wrapper trips it; plain `grep -n` does not. For match-with-context across files, use `python3` with `re.finditer` and explicit slicing.
- **`write-review` derives `scope` itself, so a count you measured earlier and typed into the Summary can contradict the record it is written into — and nothing compares the two.** [§implement-phase](framework/constitution.md#implement-phase).
- **`write-review`'s `scope` counts scope entries, not files.** A plan Affected Files pattern such as `runtime/tests/golden/*.jsonl` is one entry however many files it matches, so a Summary that counts files says how its count reconciles with `scope`.
- **Adding a member to a closed set the `check-artifacts` families use — a family, a skip reason, a marker — is a corpus sweep, and Family 18 binds only the marker lists.** Before the release commit, grep an existing sibling (`root-absent`) across `framework/`, `docs/`, `runtime/src/` and `specs/`; update every list and count naming it, or drop a needless count.
- **Relocating a frontmatter field: the readers you missed are found by the checks' own guards firing, not by grepping for them.** [§grounding](framework/constitution.md#grounding).
- **The project root is not the git work tree's root, and every path that crosses between them must be converted.** Open a repository only via `ProjectRepository::discover` (`runtime/src/primitives/mod.rs`): `to_git` in, `to_project` out (`inbox_standing` excepted). Test with `git_fixture::subdirectory_project`.
- **A command source parses paths only from git output whose shape no user setting changes.** Use `git status --porcelain` (paths from the repo root; strip what precedes the project-relative prefix), never `--short`; pass `--relative --name-only` to `git diff`, never `--stat`.
- **Since spec 062 the runtime reads a session identity from its own process environment, and a Claude Code shell always carries one.** Spawn it via `ductus_command` (both IDs unset), pass `run_as` an identity; only `main` calls `init_process_identity`. By hand, fake `CLAUDE_CODE_SESSION_ID`; delete its `.ductus/sessions/*.toml`.
- **A rule that assumes a deployed service does not fire against the runtime, a local stdio process its operator launches.** `BE-ERR-001`–`003`, `BE-LOG-001`, `BE-LOG-006`, `BE-INPUT-006`, `BE-TRACE-001`, `BE-POOL-001` never fire; `BE-PAYLOAD-001` and `fetch-archive`'s outbound rules still do. Name the boundary first.
- **A new rule category must be registered in its file's introducing-spec data-model in the same change, or `/ductus:analyze` rejects the whole rule file.** `framework/reference/analyze.md` (*Which ID format governs a file*) reads it first; `scripts/lint-rule-ids.sh` accepts any category. Update the data-model and the file's header format line together.
- **`eprintln!` panics when stderr is a pipe whose reader has gone, so a warning the runtime prints on every run can fail the run.** Use `let _ = writeln!(std::io::stderr(), …)`, as `warn_unknown_keys` does; prove it with `std::io::pipe()` and the reader dropped (`runtime/tests/config_unknown_keys.rs`), not `2>&-`.
- **An interrupted turn silently kills the background agents launched in it.** After an interrupt or rejected tool call, `stat -L` each agent's `.output` symlink (mtime stopped at the interrupt means dead), check its target files, and relaunch the dead with the same brief.
- **A background agent that launches its own background agents hands back before they finish, then resumes as each reports.** Brief a measuring agent to work in its own foreground rather than fan out, or, once its final report is in and its sub-agents' files exist, stop it with `TaskStop`; their files survive.
- **A background agent's hand-back can arrive cut off mid-sentence, and a cut-off report is not a read.** Ask for a resend with `SendMessage` before stopping it, and act only on the full text. Brief agents to end the report text with a marker line such as `END OF REPORT`.
- **Invoke the runtime as `runtime/target/release/ductus` or through the `mcp__ductus__*` tools — a bare `ductus` in a shell may not be the runtime.** In the owner's interactive shell `ductus` is an alias that changes into the checkout, so `ductus <primitive>` from Bash does the wrong thing.
- **Identify a request to an outside service by this repository's URL, never by a person's email address.** Send `ductus <tool> (https://github.com/stonean/ductus)` as the User-Agent, per `scripts/check-runtime-currency.sh`. Any brief that may reach a registry states this rule in the shared brief file.
- **A destination check judges where a write lands, not only where its path leads, and compares names as the file system folds them.** Judge the parent resolved with the final name as given and the whole path resolved (`write_atomic_bytes` replaces a link, never follows it), and compare names after `host_config::fold`. Write the bytes the check judged; find the root among the path's resolved ancestors; judge an exception's own parameter; list every caller before granting a shared check an exception. Prove each refusal from the base where it alone refuses, by its own mutation, with the whole cell table beside the tests, as `runtime/src/primitives/host_config.rs` keeps it.
- **An exact allow rule bounds the command text, not every way to run it — probe a narrowed permission rule against the commands the steps spell and against hostile forms before claiming it bounds anything.** Claude Code strips a bare `xargs` before matching, so `echo x | xargs cp a b` runs `Bash(cp a b)` with operands appended; Antigravity's `command(...)` rules are token prefixes; zsh glob qualifiers (`*(e:'cmd':)`) run code, so a regex argument class (Auggie's `shellInputRegex`) excludes parentheses. Test what each rule admits and refuses (separators, substitution, redirects, `xargs`, zsh qualifiers, `run-generator`, `exec`; `re.search` for regexes) and disclose what it still admits.
- **Two traps in this repo's audit scripts and in `ductus.md`'s tables.** In `"$(...)"`, bash 3.2 misparses a backticked heredoc: use a function; test in `/bin/bash`. `check-artifacts` reads a `ductus.md` row whose 2nd cell is one code span as a destination; use bullets.
- **With anything under `runtime/` staged, the pre-commit hook outlasts one Bash call — commit in the background, and never wait on it with `pgrep -f`.** The hook runs `cargo clippy` and `cargo test`, which can top 600 s. Commit with `run_in_background`; await its notice or poll `git log -1`. `pgrep -f` matches its own loop, so use `'[g]it commit'`.
- **An installer change can be exercised without a push: drive `apply-manifest` and `enforce-manifest` from a staging copy of `framework/`.** `cp -R framework` to a `mktemp -d` `--source-root`; build `--entries-json` from its `bootstrap/ductus.md`. On `main`, a subagent (no nested CLI) runs `install.sh` in scratch, no `mcp__ductus__*`.

## Boundaries

- **No host-level enforcement of the deterministic (`ductus`) path — it is a deliberate non-goal.** `/ductus`'s State-A contract (spec 029, scenario `state-a-deterministic-path-forcing`) binds by procedure language only; do not propose denying `curl`/`tar` or a shell-stripped State-A variant.
- **Never edit an installed command file directly — edit the source the generator copies from.** [§drift-prevention](framework/constitution.md#drift-prevention).
- **Never end a response with a "worth flagging" / "worth noting" / "two things to note" section. Every residue gets a disposition, not a paragraph.** [§design-principles](framework/constitution.md#design-principles).

## Design Principles

- **Reach for a runtime primitive first; a shell script is the fallback.** [§runtime-boundary](framework/constitution.md#runtime-boundary).
- **A check that cannot run must never look like one that passed.** [§design-principles](framework/constitution.md#design-principles).
- **Never close work with a caveat attached — the status is the claim, and a summary is not where residue lives.** [§design-principles](framework/constitution.md#design-principles).
- **Never design framework features that depend on human diligence or discipline.** [§design-principles](framework/constitution.md#design-principles).
- **Removing an embedded copy is a corpus sweep, not a deletion — grep for what pointed at it, including the artifacts that *describe* it.** [§drift-prevention](framework/constitution.md#drift-prevention).
- **A `data-model.md` that claims "authoritative shapes" drifts from the runtime silently — check it against a record the runtime actually wrote, not against the code.** [§drift-prevention](framework/constitution.md#drift-prevention).
- **Point at the canonical source — never embed a copy of it.** [§drift-prevention](framework/constitution.md#drift-prevention).
- **A conformance test whose subject is drawn from corpus state can go vacuous, and its vacuity guard will then assert that an unhealthy corpus must exist.** [§design-principles](framework/constitution.md#design-principles).
