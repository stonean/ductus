# Allowlist for files under framework/commands/ or framework/bootstrap/
# that are allowed to return ParseError::LegacyProse — that is, that carry
# no parseable Instructions section (numbered steps + backtick-quoted
# primitive names + HTML-comment extension markers).
#
# Consumed by scripts/lint-procedure-parseability.sh, which globs both
# framework/commands/*.md and framework/bootstrap/*.md. Each non-blank,
# non-comment line is a repo-relative path to a file in one of those two
# trees.
#
# Entries are of two kinds, and they are not retired the same way:
#
#   TRANSITIONAL — a slash command not yet rewritten to the parseable
#   conventions. Removed as each is rewritten (spec 022's tasks 12-17 and
#   the follow-on scenarios for /ductus:clarify, /ductus:review,
#   /ductus:groom). If one of these ever starts parsing as a real
#   procedure, that is a win and the entry goes.
#
#   REFERENCE PROSE — a file that is prose by design and will never carry
#   an Instructions section, because nothing dispatches from it. Permanent.
#   Giving such a file a synthetic Instructions section to score a clean
#   parse would be a false claim about what the runtime executes, and would
#   additionally oblige check_step_references.rs's BOOTSTRAP_FILES to cover
#   a file whose steps no walker runs.
#
# Files NOT in this list must parse cleanly as a Procedure under
# `ductus parse --check`. Files in this list MAY return legacy-prose
# without failing CI — but an Invalid parse (malformed structure) fails
# the lint even for listed files.
